# HACKALEM AI — управление заказами поставщикам

HACKALEM AI — прототип системы поддержки закупок для менеджеров, которые формируют заказы поставщикам. Решение принимает историю продаж и складские данные, исключает нетипичные крупные продажи, прогнозирует спрос, учитывает периоды отсутствия товара и формирует объяснимые рекомендации по объёму заказа.

Проект помогает заменить ручной анализ таблиц единым сценарием: загрузить данные, выполнить расчёт, изучить рекомендации и причины, скорректировать план, сравнить поставщиков и выгрузить результат.

## Что реализовано

- загрузка и проверка файлов CSV, XLSX и XLS;
- распознавание русских и английских названий колонок, включая формат выгрузки из 1С;
- предварительная сводка по загруженному файлу без возврата сырых клиентских данных;
- обнаружение крупных разовых продаж методом IQR и исключение их из регулярного спроса;
- агрегация истории продаж по месяцам;
- прогноз следующего периода методом экспоненциального сглаживания Holt–Winters;
- учёт тренда артикула и категории;
- компенсация скрытого спроса за периоды отсутствия товара на складе (`stockout`);
- расчёт рекомендуемого количества с учётом текущего остатка и товаров в пути;
- определение срочности заказа и ближайшего сезонного пика;
- REST API для загрузки, расчёта, просмотра, корректировки и утверждения заказов;
- веб-интерфейс с восемью разделами: загрузка, дашборд, детализация, аномалии, подбор поставщика, аналитика, утверждение и экспорт;
- фильтрация рекомендаций по складу, категории, поставщику и срочности;
- графики истории спроса, отметки периодов stockout, аналитика категорий и сезонный календарь;
- AI-анализ рыночных трендов по категориям с веб-поиском и ссылками на источники;
- AI-поиск до трёх альтернативных предложений поставщиков в Казахстане;
- экспорт текущего плана в CSV, XLSX и PDF;
- автоматические тесты расчёта, API-контракта и AI-сервиса.

## Как работает решение

1. Исходные данные передаются в `POST /upload` в виде CSV/XLSX/XLS-файла. Парсер приводит названия колонок к единому формату и проверяет обязательные поля.
2. `POST /calculate` запускает расчёт. Продажи агрегируются по артикулам и месяцам, крупные разовые операции исключаются IQR-детектором.
3. Модель прогнозирует спрос на следующий период. К прогнозу добавляется оценка недополученного спроса во время stockout, затем вычитаются остаток и товары в пути.
4. Результат сохраняется в памяти процесса и доступен через `GET /orders`; исключённые операции — через `GET /anomalies`.
5. Веб-интерфейс загружает эти ответы и строит дашборд, детализацию артикула, аналитику по категориям и календарь закупок.
6. При наличии ключа OpenAI пользователь может запросить рыночные тренды или альтернативных поставщиков. Ключ остаётся на сервере и не передаётся в браузер.
7. План можно скорректировать, сгруппировать по поставщикам и экспортировать в нужный формат.

## Технологии

### Backend и расчёты

- Python;
- FastAPI и Uvicorn;
- Pydantic;
- pandas и NumPy;
- statsmodels (`ExponentialSmoothing` / Holt–Winters);
- openpyxl для Excel-файлов;
- python-multipart для загрузки файлов;
- python-dotenv для переменных окружения.

### Frontend

- HTML5, CSS и Vanilla JavaScript;
- Tailwind CSS через CDN;
- Chart.js через CDN;
- SheetJS для экспорта XLSX;
- jsPDF и jsPDF-AutoTable для экспорта PDF;
- встроенный шрифт Roboto с кириллицей для PDF.

### AI и внешние API

- OpenAI Responses API;
- инструмент OpenAI `web_search`;
- модель по умолчанию — `gpt-5.6-terra`;
- модель можно заменить переменной окружения `OPENAI_MODEL`.

## Архитектура проекта

```text
Браузер
  ├─ index.html + style.css + app.js
  ├─ GET /orders, GET /anomalies
  └─ POST /ai/*
             │
             ▼
FastAPI (main.py)
  ├─ parser.py       — чтение и валидация CSV/Excel
  ├─ calculation.py  — аномалии, прогноз, stockout и рекомендации
  ├─ ai_service.py   — OpenAI Responses API и web_search
  └─ StaticFiles     — раздача фронтенда с корневого URL
```

Основные файлы:

| Файл | Назначение |
|---|---|
| `main.py` | FastAPI-приложение, API-маршруты и раздача фронтенда |
| `parser.py` | Чтение файлов, нормализация колонок и валидация |
| `calculation.py` | Прогнозирование, IQR-детектор, stockout и рекомендации |
| `ai_service.py` | Рыночные запросы к OpenAI и обработка ответов |
| `index.html` | Разметка восьми разделов интерфейса |
| `app.js` | Загрузка данных API, визуализация, локальные корректировки и экспорт |
| `style.css` | Стили интерфейса |
| `tests/` | Тесты вычислений, API и AI-интеграции |

### API

| Метод | Маршрут | Назначение |
|---|---|---|
| `POST` | `/upload` | Загрузить и проверить исходный файл |
| `POST` | `/calculate` | Выполнить расчёт; доступны фильтры `warehouse` и `category` |
| `GET` | `/orders` | Получить текущие рекомендации и исключённые аномалии |
| `GET` | `/anomalies` | Получить список исключённых операций |
| `POST` | `/orders/{sku}/adjust` | Изменить рекомендуемое количество и сохранить причину |
| `POST` | `/orders/approve` | Сформировать сгруппированный по поставщикам план для экспорта |
| `POST` | `/ai/market-trends` | Получить AI-сводку трендов категории |
| `POST` | `/ai/market-alternatives` | Найти альтернативных поставщиков |

Интерактивная документация API доступна по адресу `http://127.0.0.1:8000/docs`.

## Формат входных данных

Обязательные колонки:

| Каноническое имя | Содержание |
|---|---|
| `sku` | Артикул товара |
| `date` | Дата продажи |
| `quantity` | Проданное количество |
| `price` | Цена |
| `client_id` | Обезличенный идентификатор клиента |
| `warehouse` | Склад |
| `stock` | Остаток на складе |

Дополнительно поддерживаются `in_transit`, `name`, `category`, `supplier` и `lead_time_days`. Для отсутствующих необязательных полей расчёт использует значения по умолчанию. CSV читается в UTF-8 с BOM, а при ошибке декодирования — в CP1251.

## Установка и запуск

### Требования

- установленный Python и `pip`;
- доступ в интернет для установки Python-пакетов и загрузки frontend-библиотек с CDN;
- ключ OpenAI нужен только для AI-функций.

Точная версия Python в репозитории не зафиксирована.

### Быстрый запуск в Windows

Из корня репозитория запустите:

```bat
start.bat
```

Скрипт установит зависимости, откроет браузер и запустит Uvicorn. Приложение будет доступно по адресу:

```text
http://127.0.0.1:8000
```

### Ручной запуск

```bash
python -m venv .venv
```

Активация виртуального окружения в Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

Активация в Linux/macOS:

```bash
source .venv/bin/activate
```

Установка зависимостей и запуск:

```bash
python -m pip install -r requirements.txt
python -m uvicorn main:app --reload
```

Команду запуска необходимо выполнять из корня репозитория: от текущей директории зависит поиск статических файлов.

### Настройка AI-функций

Создайте в корне файл `.env`:

```dotenv
OPENAI_API_KEY=ваш_ключ
OPENAI_MODEL=gpt-5.6-terra
```

`OPENAI_MODEL` необязателен. Без `OPENAI_API_KEY` основной расчёт и интерфейс работают, но AI-маршруты возвращают понятную ошибку `502`.

## Как проверить решение

В репозитории есть воспроизводимый CSV-сценарий `tests/fixtures/must_have_anomaly.csv`.

1. Запустите сервер.
2. Загрузите fixture через Swagger UI (`/docs`) методом `POST /upload`, указав `mode=custom`, либо выполните в Windows:

   ```powershell
   curl.exe -X POST "http://127.0.0.1:8000/upload" `
     -F "mode=custom" `
     -F "file=@tests/fixtures/must_have_anomaly.csv;type=text/csv"
   ```

3. Запустите расчёт:

   ```powershell
   curl.exe -X POST "http://127.0.0.1:8000/calculate"
   ```

4. Откройте или обновите `http://127.0.0.1:8000`.
5. На дашборде проверьте рекомендацию для артикула `ABC-123`.
6. Откройте детализацию артикула: интерфейс покажет месячную историю, обоснование и период stockout.
7. На вкладке «Аномалии» должна появиться крупная разовая продажа клиента `anon-outlier`, исключённая из прогноза.
8. Откройте «Аналитика / Тренды» и проверьте график категории и сезонный календарь.
9. На вкладке экспорта скачайте результат в CSV, XLSX или PDF.

Для запуска автоматических тестов:

```bash
python -m unittest discover -s tests -p "test_*.py" -v
```

Тесты проверяют, что выброс не изменяет рекомендацию, stockout увеличивает потребность, API сохраняет контракт данных, а AI-запросы используют веб-поиск и строгую JSON-схему.

## Данные и интеграции

- Источник расчётных данных — загружаемые пользователем CSV/XLSX/XLS-файлы.
- Код содержит набор алиасов колонок для русскоязычных выгрузок и упрощённого формата 1С, но прямого подключения к базе 1С нет.
- После запуска сервер содержит небольшой встроенный демонстрационный результат. Реальная загрузка заменяет его результатом текущего расчёта.
- Расчётные данные, корректировки backend и утверждения backend хранятся только в памяти процесса.
- Ручные позиции, изменения и утверждения, сделанные через текущий интерфейс, сохраняются в `localStorage` браузера.
- OpenAI Responses API используется для рыночных трендов и поиска альтернатив; `web_search` предоставляет актуальные внешние источники.
- Tailwind CSS, Chart.js, SheetJS, jsPDF и jsPDF-AutoTable загружаются из публичных CDN.

## Ограничения текущей версии

- Данные не сохраняются в базе и теряются после перезапуска сервера.
- Состояние рассчитанных заказов является общим для процесса и не разделено по пользователям или сессиям.
- В интерфейсе элементы загрузки файла и кнопка «Запустить расчёт» пока не подключены к `/upload` и `/calculate`; полный сценарий загрузки выполняется через Swagger или REST API.
- Корректировки и утверждения, сделанные в интерфейсе, сохраняются локально в браузере и пока не вызывают реализованные backend-маршруты `/orders/{sku}/adjust` и `/orders/approve`.
- Утверждение заказа не отправляет его поставщику; API формирует только готовую к экспорту структуру.
- Кнопка возврата аномалии в расчёт не подключена к backend-операции.
- Переключатели периода `All / 1M / 5M / 1Y` в аналитике пока не меняют диапазон графика.
- Аналитика по категориям собирается на клиенте из истории `/orders`; оценка риска использует эвристику на основе срочности, а не отдельную модель риска backend.
- Для определения сезонного пика требуется не менее 24 месяцев истории и наличие всех 12 месяцев; иначе дата пика не формируется.
- AI-функции зависят от действующего ключа OpenAI, доступа аккаунта к выбранной модели, лимитов API и доступности веб-поиска.
- Frontend-зависимости загружаются с CDN, поэтому без интернета часть интерфейса и экспортов может быть недоступна.
- В `requirements.txt` не закреплены версии пакетов, поэтому полностью воспроизводимая сборка пока не гарантирована.
- Парсер принимает расширение `.xls`, но отдельный движок для старого формата Excel в зависимостях явно не указан.
- Аутентификация, разграничение прав, многопользовательская работа и production-конфигурация сервера не реализованы.

## Развёрнутая версия

Публичная deployed-версия и конфигурация облачного развёртывания в репозитории не обнаружены. Проект запускается локально через `start.bat` или Uvicorn.
